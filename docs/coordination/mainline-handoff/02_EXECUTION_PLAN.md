# 主线执行计划

## 总体原则

当前只保留一个由用户指定的主线执行方。两个专项设计执行方只产出互相独立的设计诊断与原型，
不修改正式前端、不合并、不发布。用户保留产品批准、外部副作用、敏感开关和 Production 最终授权。

## 阶段 0：只读接管与基线复核（立即）

1. 按 `AGENTS.md` 的顺序读取长期工作流、V020 计划/状态、当前 Run 和本交接包全部文件。
2. 在正式集成工作树核对 branch、HEAD、`origin/main`、远端可达性和完整工作树状态。
3. 确认 `.tmp-v020-rc2/`、`.tmp-v020-rc4/` 是保留证据，不删除、不提交、不格式化。
4. 复核 RC6 source SHA、manifest、workflow run、部署后备份和隔离恢复记录之间的一致性。
5. 运行协调账本验证；若仍是历史 safe-scan budget 超限，只记录 blocker，不重写历史，不派发依赖账本的并行写任务。

阶段 0 不修改业务代码，不启动本机 Docker，不发送邮件，不执行 Production 动作。

## 阶段 1：V20-15 剩余门禁

### 1A. 认证 UX 回归

- 使用用户明确登录的同一可控会话；不得读取 Cookie、localStorage、密码或会话文件。
- 覆盖 21 个受保护路由，重点操作 `/app/today`、`/app/review`、Workspace、Space、邀请、搜索、
  Settings、Profile、Security、Sync、Data、Integrations 与 AI。
- 验证成功、失败、空值、loading、disabled、防重复提交、权限、离线和恢复建议。
- 复测邀请冲突 409 的可行动中文提示，但不实际向真实邮箱发送邀请。
- 验证 1440/1024/390/320 px、明暗主题、键盘、焦点、移动知识节点列表、桌面图谱键盘导航、
  主题持久化 XSS 防护和浏览器控制台错误。

### 1B. 24 小时观察收口

- 观察期起点：`2026-08-09T22:59:03Z`。
- 到点后重新核对公网/loopback health、API ready source SHA、容器镜像、OOM/restart、日志、磁盘、
  内存、Swap、备份新鲜度、异机同步状态和告警。
- 任何检查失败都保留断点，不清理 RC2 回滚点，不进入 Production 决策。

### 1C. 需用户单独批准的动作

- 真实受邀邮箱投递；
- 实体移动设备验收；
- Production 宣告、流量切换、旧回滚点清理；
- Shared Write、Deletion、Attachment、Local Worker、Provider、sync-v1、AI Acceptance 任一启用。

## 阶段 2：双方案前端重设计（仅设计，不施工）

两个专项设计执行方基于相同产品事实独立完成：产品诊断、UX 审查、信息架构、交互、视觉、
Design System 和高保真交互原型。要求：

- 使用不同 worktree/分支和不重叠输出目录；固定同一 approved base。
- 不修改 `apps/web/src/**`、API、权限、迁移、OpenAPI、Provider、生产配置或部署文件。
- 可以使用隔离原型自己的开源 UI/图谱/布局依赖，但必须固定版本并记录许可证、可访问性、维护、包体与供应链评估；
  不得修改根 manifest/lockfile，正式接入前另行审查。
- 覆盖桌面和移动、明暗主题、所有关键状态与知识图谱等价路径。
- 先提交诊断和方案，再提交可操作原型；不得只做截图或颜色替换。
- 用户审批前停止，不自行把方案接入产品。

完整任务包见 `07_FRONTEND_REDESIGN_BRIEFS.md`。

## 阶段 3：用户方案审批与冻结

用户从两个方案中选择一个，也可以要求组合修订。批准时必须冻结：

- 导航与信息架构；
- 核心任务流和交互反馈；
- 页面/组件/状态矩阵；
- Design System token 与明暗主题；
- 1440/1024/390/320 px 响应式行为；
- 正式施工范围、非目标和迁移策略。

没有明确批准，不进入阶段 4。

## 阶段 4：主线实施已批准原型

主线执行方从最新批准基线创建独立分支，按页面簇分批实施。每批必须运行目标测试、Web 全量测试、
Lint、TypeScript、生产构建、相关 Playwright、axe、响应式和主题门禁，并返回结构化 handoff。

正式实现只能复用现有 API/数据/权限语义；设计中发现合同缺口时停止并单独提案，不在前端静默伪造。

## 阶段 5：版本决策

V20-15 剩余门禁与批准前端实施都通过后，用户决定：

1. 收口 v0.2.0 Production；或
2. 先作为受控 prerelease 继续观察；或
3. 进入 v0.2.1 设计门。

v0.2.1 仍聚焦本地解析与论文证据工作台；先完成 ADR、威胁模型、容量、离线和 Provider 数据范围，
再实现 PDF 定位、公开元数据、引用摘录和受控本地 Worker。

## 统一停止条件

- 基线、分支、允许路径、用户批准或外部副作用不明确；
- 工作树出现未知修改，或并行写路径重叠；
- head SHA、manifest、运行镜像、迁移头或备份证据不一致；
- 任一测试、审计、恢复、认证、响应式、无障碍或运行时检查失败；
- 需要读取/写入秘密、私有主机数据、用户目录或真实用户内容；
- 需要打开任何未批准生产开关、绕过 SessionBoundary 或改变 sync-v1。

停止后记录真实原因、保留现场，不伪造通过，不进入下一阶段。
