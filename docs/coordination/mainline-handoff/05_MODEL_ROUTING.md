# 执行方职责与路由（当前决策）

## 当前启用

| 角色                 | 状态     | 当前职责                                                    |
| -------------------- | -------- | ----------------------------------------------------------- |
| 用户指定的主线执行方 | 主线启用 | 只读接管、V20-15 收口、实现、测试、问题修复和结构化 handoff |
| 专项设计执行方 A     | 仅设计   | 产品/UX/IA/交互/视觉/Design System 诊断与独立原型           |
| 专项设计执行方 B     | 仅设计   | 代码感知的完整诊断、状态矩阵、交互规范与独立高保真原型      |
| 用户/产品 owner      | 最终批准 | 方案选择、外部副作用、敏感开关、Production 和发布授权       |

两个专项设计执行方不是并行正式前端开发者。它们只能使用独立 worktree/分支和不重叠的设计输出目录，
不得修改 `apps/web/src/**`，不得 commit/merge/push/release。用户批准一份完整原型后，正式施工统一交给
主线执行方，避免两个实现分叉。

## 暂停或按需启用

| 角色/工具           | 状态     | 说明                                                                         |
| ------------------- | -------- | ---------------------------------------------------------------------------- |
| 其他实现执行方      | 暂停     | 不为填满模型席位而派发；只有独立收益明确且用户批准时启用                     |
| 只读安全/合同审查   | 按需     | 涉及认证、权限、迁移、秘密、外部连接器或 Production 前提醒用户配置合适审查方 |
| 纯内存 graph kernel | 候选隔离 | 技术验收通过但缺少正式授权、scope、游标和资源治理，不接入生产 API            |

## 选择专项模型的提醒条件

以下场景应暂停主线实现并提醒用户配置更适合的模型或独立审查：

- 大规模视觉探索、图像生成或多套品牌方向比较；
- 认证、加密、权限、迁移、支付、外部发送或供应链安全变更；
- 超长上下文的全仓架构迁移；
- PDF/OCR/多模态原型或真实移动设备专项；
- 发布前需要与实现方分离的只读终审。

## 配置与中转规则

- 执行方和模型 ID 必须在每个任务启动时实际核对；套餐名不等于模型证据。
- 第三方 CLI hooks 曾造成登录问题，任何执行方不得擅自新增 hooks 或修改用户 CCSwitch/Provider 配置。
- 上游中转 API 400 属于模型接入链路问题，不得写成产品功能通过或失败证据。
- 任务包不得包含 API key、Token、密码、Provider endpoint、私有主机、用户目录或终端转录。

## 授权边界

主线身份不自动包含 Git 或发布权。Commit、push、merge、release、真实邮件、Production、流量切换、
回滚点清理和敏感能力启用均以用户最新明确授权为准。
