# 模型职责与路由（当前决策）

## 当前启用

| 模型/工具 | 状态 | 当前职责 |
| --- | --- | --- |
| GLM / ZCode | 主线启用 | 读取交接包、实现、测试、修复、提交结构化 handoff |
| Windows Codex | 协调/验收（按用户调用） | 基线核对、独立验证、状态文档、Git 集成和发布门禁 |

## 暂停或归档

| 模型/工具 | 状态 | 说明 |
| --- | --- | --- |
| Kimi / Claude CLI | 暂停 | 第一版原型和一次性前端施工已结束；不得默认派发后续前端迭代 |
| DeepSeek / OpenCode | 暂停 | DeepSeek 只读终审已完成；OpenCode 不再作为当前主线执行者 |
| GLM 纯内存 graph kernel | 候选隔离 | 技术验收通过但缺少正式授权、scope、游标和资源治理，不接入生产 API |

## 配置与中转规则

- Kimi/Claude 的 hooks 曾造成登录问题，用户删除后恢复；任何模型都不得擅自新增 hooks 或改动 CCSwitch/Provider 配置。
- 过去出现的上游中转 API 400 属于模型接入链路问题，不得写成产品功能通过或失败证据。
- 用户若以后指定其他模型，必须重新生成自包含任务包，明确模型 ID、只读/可写范围、验收命令和停止条件。

## 授权边界

GLM 主线不等于自动拥有产品发布权。产品方向、生产开关、真实邮件、数据迁移、merge/push/release 和流量切换仍需要用户/协调者明确批准。
