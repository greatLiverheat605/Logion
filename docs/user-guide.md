# Logion 已完成功能与系统操作手册

本文面向 Logion 的实际使用者和最多 10 人的小组管理员，说明当前代码中已经实现的功能、推荐操作顺序、数据边界和常见状态。本文不把规划中的能力写成已完成功能，也不包含部署密钥、账号、域名或其他私密信息。

## 1. 产品定位与使用边界

Logion 是一个离线优先的长期学习与研究工作系统。它把目标、阶段、任务、专注会话、笔记、资料、证据、人工验收、复习、备考、自主学习、研究和小组审阅连接成可追溯的闭环。

- 适合个人以及最多 10 人的小规模自托管协作。
- 保留 Workspace、私有/共享空间、邀请、角色权限与审计能力。
- 不包含计费、套餐、公开营销站或面向公众的运营后台。
- 默认使用受邀或关闭注册；生产环境不允许开放注册。
- AI 是可选增强层。未配置 AI Provider 时，其他学习功能仍可独立使用。
- AI 输出始终是草稿，不能自动改变正式任务、掌握度、研究结论、验收结果或权限。

## 4. 推荐的首次使用流程

### 第一步：登录或接受邀请

1. 打开 Logion。
2. 已有账户时，在登录页输入邮箱和密码，或选择“使用 Passkey 登录”。
3. 新成员应从管理员发送的邀请入口进入；普通用户不能在生产环境自由注册。
4. 如果系统要求邮箱验证，先完成验证再继续。

预期结果：登录后进入“今日”页面，左侧出现当前 Workspace，以及与所选画像匹配的主功能入口。

### 第二步：确认 Workspace 和空间

1. 点击左侧“当前工作区”，或进入“工作区”。
2. 个人笔记、个人错题和未提交草稿优先放在私有空间。
3. 只有需要共同审阅的对象才进入共享空间。
4. 管理员可在“成员与邀请”中邀请成员并设置角色。

预期结果：页面显示当前 Workspace、空间和本人角色；没有权限的操作按钮保持禁用。

### 第三步：解锁本地资料

1. 进入“计划”“今日”“资料与笔记”等离线页面。
2. 选择 Workspace 和空间。
3. 输入本地口令并点击“解锁资料”。
4. 首次使用会初始化端侧加密 Vault；以后使用同一口令解锁。

注意：本地口令用于浏览器端加密，不会在普通页面回显。请妥善保存；清除浏览器站点数据前应先完成同步或导出。

### 第四步：创建学习目标和路线

1. 进入“计划”。
2. 填写目标名称、可验收成果、每周投入和目标日期。
3. 创建首个阶段，填写预计时间和验收标准。
4. 保存目标并同步。

建议：目标描述“完成后能展示什么”，阶段描述“下一段可以验收什么”，不要只写“学习某课程”。

### 第五步：在今日页面执行

1. 进入“今日”，查看 NEXT ACTION 和今日执行序列。
2. 创建或选择能够在一次专注中完成的任务。
3. 开始专注会话并记录实际投入。
4. 任务完成后提交文本、链接、笔记或资料作为证据。
5. 在“证据与人工验收”中明确提交验收决定。
6. 验收通过后再关闭任务。

重要规则：专注计时结束不等于任务完成；提交证据也不等于验收通过。

### 第六步：记录 Markdown 笔记和资料

1. 进入“资料与笔记”。
2. 在“新建 Markdown 笔记”中填写标题和正文。
3. 使用标题、列表、引用和代码块组织内容。
4. 在安全预览中检查结构；预览不会执行 HTML。
5. 外部网页使用“登记外部资料”；PDF 使用页码索引定位。
6. 保存后可在任务证据中引用对应笔记或资料。

### 第七步：建立主动回忆与复习

1. 进入“复习与掌握”。
2. 先建立知识点和必要的先修关系。
3. 为容易遗忘的知识点创建主动回忆题。
4. 作答后记录信心、结果和错因。
5. 明确确认掌握等级，并安排每日或每周复习。
6. 定期创建学习审查，记录阻塞和调整。

### 第八步：使用备考、自主学习或研究流程

备考：

1. 创建考试和日期。
2. 添加科目、权重和大纲节点。
3. 安排模考并记录得分和实际用时。
4. 根据真实覆盖率和成绩趋势安排补救任务。

自主学习：

1. 将临时想法放入快速收件箱。
2. 把值得长期推进的内容整理为学习路线。
3. 创建具有明确交付物的项目。
4. 项目完成后保存成果证据。

研究：

1. 创建研究问题。
2. 建立声明，并关联支持证据、反证或不确定证据。
3. 记录实验运行和指标。
4. 只有在证据足够时才确认结论。

### 第九步：进行小组审阅

1. 进入“导师与小组”，选择共享空间。
2. 由有权限的成员建立 Rubric。
3. 创建审阅并收集反馈与建议动作。
4. 反馈确认后生成不可变报告快照。
5. 私有笔记、错题和未提交草稿不会自动进入共享视图。

### 第十步：可选使用 AI

1. 管理员在“AI Provider”中配置兼容 Provider。
2. 明确触发连接测试和模型发现。
3. 建立任务路由。
4. 在 AI 工作区选择 Workspace、来源和输出目标。
5. 执行发送前预检，确认将离开本系统的数据。
6. 创建运行并等待草稿。
7. 在草稿审查台编辑、批准或拒绝。

不要把 AI 草稿当作已经确认的学习结果或研究结论。

### 第十一步：复用模板和只读分享

1. 进入“模板与分享”。
2. 从现有目标创建模板，或导入经过检查的结构化模板包。
3. 检查来源、版本、许可和外部链接。
4. 安装时生成独立副本。
5. 需要对外展示时，只选择必要字段并设置较短有效期。
6. 分享完成后及时撤销链接。

### 使用互操作中心（可选）

1. 使用学、研或导画像时，从“设置”选择“打开互操作中心”；也可直接访问 `/app/integrations`。
2. 在“数据工作区”选择已有 Workspace。页面数字只来自该工作区的真实记录。
3. 创建 Calendar Feed 后立即复制一次性 URL；关闭提示前先保存，停用时点击“撤销”。
4. 导入 Markdown、CSV、BibTeX 或 Logion JSON 时先查看计数与警告，再选择本人的 Private Space 并确认 `IMPORT`。
5. 导出前重新登录以满足近期认证，输入 `EXPORT` 创建任务；完成后下载文件并核对页面 SHA-256 与包内 `manifest.json`。
6. “尚未支持”的第三方账号、Webhook、MCP/API Token 和自动化卡片仅说明边界，不提供凭据输入或保存。

一次性 Calendar URL 不会持久化到前端设置、通知或日志。丢失后不能重新查看，应撤销旧 Feed 并新建。互操作中心不会读取浏览器 Cookie、密码库或第三方密钥，也不会绕过 Workspace/Space 权限。

### 第十二步：检查同步与冲突

1. 进入“同步与设备”。
2. 查看本地 Outbox、最后同步位置和附件队列。
3. 网络恢复后点击同步。
4. 出现冲突时比较本地与远端版本。
5. 根据实际内容选择保留本地、保留远端、合并或暂不处理。
6. 权限、删除、层级和验收冲突应优先人工确认。

部署者需要验证真实跨设备同步时，按照 [阿里云真实同步验收手册](../infra/runbooks/aliyun-real-sync-acceptance.md) 执行。不要用同一浏览器的两个普通标签页代替两个独立设备，也不要在同步失败时清除站点数据。

### 第十三步：维护账户和数据

账户安全：

- 检查登录设备，撤销不认识或不再使用的设备。
- 优先添加 Passkey，并启用 TOTP。
- 将一次性恢复码离线保存。

数据主权：

- 定期创建加密导出。
- 导入前先查看预览和风险提示。
- 清除浏览器、卸载旧版本或迁移服务器前，先确认同步、导出和备份均成功。
- 账户删除属于高风险操作，应确认恢复窗口和备份策略后执行。

## 6. 页面状态与常见问题

### “请先解锁”

当前页面需要访问端侧加密数据。请选择 Workspace 和空间，输入正确的本地口令后解锁。

### “网络暂不可用”

页面仍可把受保护修改保存到本机 Outbox。不要反复创建相同对象；网络恢复后进入“同步与设备”执行同步并检查冲突。

### 按钮不可点击

常见原因包括：

- 尚未选择 Workspace 或空间；
- 尚未解锁本地资料；
- 缺少前置对象，例如没有目标时不能从目标创建模板；
- 当前角色没有该操作权限；
- 当前功能依赖尚未配置的邮件服务、Passkey 环境或 AI Provider；
- 正在离线执行只允许服务端完成的操作。

### 出现同步冲突

冲突不是普通报错。它表示两个设备或成员修改了同一对象，系统无法在不丢失语义的情况下自动决定。请查看两边内容后明确处理。

### 页面没有图表或趋势

图表只使用真实记录。没有任务、会话、复习、成绩或实验数据时，页面展示真实空状态，不生成示例数值。

### Passkey 不可用

确认使用受支持的浏览器、HTTPS 域名以及正确的 WebAuthn Origin。HTTP 仅可在受信任的本地开发环境使用。

## 7. 管理员日常检查清单

建议每周检查：

1. 服务健康状态、数据库和 Redis 就绪状态；
2. 备份是否成功，以及恢复验证是否通过；
3. 待处理邀请、异常登录设备和安全审计事件；
4. 同步冲突、失败附件和积压 Outbox；
5. 即将到期的只读分享；
6. AI Provider 健康状态和待审草稿；
7. 磁盘空间、证书有效期和外部邮件投递状态。

## 8. 当前限制

- 真实邮件投递适配器、域名、TLS 和 Windows 异机加密备份需要部署者配置。
- 物理 iOS/Safari、人工屏幕阅读器和目标云服务器容量仍应在实际环境验证。
- PWA 尚不支持受保护工作台的完整离线冷启动，也不等同于原生手机应用。
- 离线数据依赖浏览器 IndexedDB 和 Web Crypto；无痕模式或主动清理站点数据可能导致未同步数据丢失。
- 设备撤销能阻止新的服务端访问，但不能远程擦除长期离线设备已经保存的数据。
- AI Provider 的能力和可用性由所接入服务决定，Logion 不保证第三方模型输出正确。
- 当前产品面向个人和最多 10 人的小组，不以大规模组织管理为目标。

## 9. 建议的功能评审方法

评审新功能时，建议依次回答：

1. 它解决的是哪个真实学习或研究动作？
2. 它是否能使用现有真实数据，而不是依赖示例内容？
3. 它是否需要改变权限、同步或数据模型？
4. 它在离线状态下应该如何工作？
5. 它是否会自动改变正式记录，还是只生成建议或草稿？
6. 它是否会把私有内容带入共享空间或外部 Provider？
7. 它需要哪些验收标准、浏览器测试和安全测试？

通过这七项检查后，再决定增加、调整或删除功能。
