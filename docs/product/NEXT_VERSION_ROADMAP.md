# Logion 下一版本产品与技术路线图

## 路线判断

Logion 当前最稀缺的不是功能数量，而是“可信运行、低认知负担和长期复用”。下一版本不应继续堆一级页面，而应先把 worker、认证 E2E、离线体验和跨工作台路径收紧，再扩展论文研读和外部连接器。

北极星目标：用户每周能完成更多“有证据、可复查、可恢复”的学习闭环，同时不增加数据丢失、权限误判和运维失明风险。

## 版本节奏总览

| 版本   | 主题                     | 主要结果                                             | 建议周期 |
| ------ | ------------------------ | ---------------------------------------------------- | -------- |
| v0.1.1 | 可信运行与体验收口       | worker 可观测且公平、认证门禁可信、核心页面更易用    | 3–4 周   |
| v0.2.0 | 自适应知识空间与动态图谱 | 可追溯摘录、人工确认图谱、自适应复习和核心离线连续性 | 6–8 周   |
| v0.2.1 | 本地解析与论文证据工作台 | PDF 定位、本地解析、引用问答和指标触发的语义检索     | 5–7 周   |
| v0.3.0 | 个人移动端候选           | Android/iOS/鸿蒙薄壳签名、真机与弱网门禁             | 4–6 周   |
| v0.4.0 | Connector/Automation v2  | 安全凭据、Webhook/MCP、可审计自动化                  | 独立立项 |

周期是工程规划单位，不是发布日期承诺；每个版本只有通过迁移、恢复、安全、浏览器和真机门禁后才能发布。

## v0.1.1：可信运行与体验收口

### P0：worker 可靠性

目标：后台任务失败必须可见，任何一类队列都不能被长期饿死。

> 实施进度：已完成独立 liveness/readiness、按队列连续失败阈值、PostgreSQL/Redis 探测、聚合积压指标、独立心跳和 Email/Export/AI/Deletion 轮转调度。故障注入已验证连续 3 次失败会使 readiness 失败，依赖恢复后无需重启即可恢复。

- 把 liveness 与 readiness 分开；readiness 纳入数据库/Redis、连续失败和最近成功轮询。
- 调度改为轮转或配额公平：Email、Portability、AI、Deletion 每轮都有可预测机会。
- 增加安全指标：每类 queued/running/failed、最老任务年龄、租约超时、重试次数。
- 日志增加任务类型、阶段、错误码和关联 ID；继续禁止正文、Token、邮箱动作 Token 和 Provider 凭据。
- 管理员健康页只展示聚合状态和建议动作，不显示用户内容。

成功指标：

- 注入某类持续积压时，其他三类任务的 P95 等待时间不超过 30 秒；
- 连续 3 次任务基础设施失败后 readiness 在 60 秒内变为失败；
- 恢复依赖后不重启即可自动恢复，且没有重复执行副作用。

### P0：认证 E2E 夹具与门禁可信度

目标：浏览器测试的绿色结果明确表示认证工作台真的执行过。

> 实施进度：夹具与 Release/Nightly 强制门禁已完成。2026-08-01 实测认证项目 27/27 通过，完整矩阵 91 通过、6 个 PWA 预期跳过；3000 公共项目 64 通过、6 个 PWA 预期跳过且未启用认证项目。连续 20 次观察仍是发布前稳定性任务，尚未据一次验收提前宣告完成。

- Global setup 在隔离 PostgreSQL/Redis 中为每个 worker 创建独立用户和 Workspace。
- 生成按 worker 隔离的 Playwright `storageState`，禁止共享刷新会话并发登录。
- 把 public-web、authenticated-real-stack、mobile-layout 三类 project 分开。
- 完整门禁 workflow 若认证套件被跳过则失败；报告分别列出 passed/failed/skipped 原因。
- Release/Nightly 使用一次性 Compose 数据与提高后的测试注册上限；本地重复运行仍应使用隔离测试栈，后续再补 Redis 独立 DB/前缀，禁止清空共享命名空间。

成功指标：

- Release/Nightly 中 12 主路由和关键二级路由的认证检查 100% 执行；PR 的 3000 公共项目不访问 API；
- 连续重跑 20 次无会话竞争或限流夹具失败；
- 本地 3000 纯前端测试不会误访问远程 API，远程环境无显式凭据时禁止自动注册。

### P1：核心 UI 收口

目标：减少“功能很多但不知道下一步”的感觉。

> 已批准设计方向：四画像采用“共享数据与领域工作台 + 画像首页模块化编排”的混合架构。Today 允许明显不同布局；Review、Records 等共享业务能力，只改变默认视图、信息权重和快捷动作；知识图谱只实现一个引擎并提供四种投影视图；不建设四套独立页面。统一使用中文字标或线性图标，不再混用 emoji。

> 原型流程：先由 Kimi 在相同信息架构下产出两款可交互原型——A“安静行动型”和 B“证据指挥台型”。每款覆盖 1440/390 px、明暗主题、Today 四画像、Review、Records、动态图谱及空/错/加载/离线/锁定状态。用户批准其中一款后，Kimi 负责视觉组件和页面编排；共享数据层、权限、公共契约和最终集成仍由核心负责人控制。

- Today 只保留今日状态、下一行动、快速捕获和待验收四个首要区块；低频诊断进入折叠区或二级页。
- Review 统一“到期复习、主动回忆、错因、周期审查”的进入顺序。
- Settings 按个人偏好、安全、数据、互操作分组，减少跨页面寻找。
- 所有空状态都提供一个真实起步动作；错误状态保留请求编号和恢复建议。
- 建立 6–8 个核心视觉基线：登录、onboarding、Today、Review、Records、Integrations、Settings、移动更多菜单。

成功指标：

- 首次用户从登录到创建首个今日目标的中位步骤不超过 12；
- 80% 核心任务可从当前页面一个主操作开始；
- 320/390 px、明暗主题、键盘和 axe 门禁继续全绿。

### P1：技术债首轮拆分

- 抽取 `useVaultWorkspaceRefresh`，移除七处 Hook 依赖豁免。
- Today、Review、Self-study 按数据控制器/表单命令/展示区拆分。
- `sync/push.py` 按实体族注册处理器；不改变 sync-v1 契约和校验向量。
- 为 worker 调度、健康状态和每类任务补独立单元与集成测试。

## v0.2.0：自适应知识空间与动态图谱

### 已批准产品定义

- 复用现有 `Space` 作为知识空间，不新增平行的顶层 KnowledgeBase 概念。
- 知识默认属于用户个人私有空间，只有显式操作才可分享给 Workspace 或共享 Space。
- “自学习”只指两件事：系统组织用户批准的资料，以及根据答题、信心、耗时、错因、复习和反馈调整个人学习状态；不持续训练或微调基础模型。
- AI 可以提出概念、关系、试题和摘要候选，但不能自动确认掌握度、研究结论或正式知识关系。
- PDF 原件首版默认留在本地；云端保存来源元数据、内容哈希、页码定位、用户选定摘录和已批准关系。
- v0.2.0 是独立契约版本，允许经过单独审查的数据库迁移和 OpenAPI 加法变化；不得把新实体硬塞进 sync-v1。

### P0：可追溯知识链

目标：建立“来源 → 摘录 → 知识点/试题/研究声明 → 复习”的可验证闭环。

- 新增 `source_excerpts`：来源、页码/章节/字符定位、摘录文本、来源版本、内容哈希、创建者和乐观版本。
- 新增 `knowledge_citations`：摘录指向 Topic、QuizItem、ResearchClaim 或 Note；使用受控的显式外键与“恰好一个目标”数据库约束，不使用无约束 `target_type + target_id` 或 JSON 多态关系。
- Topic 与 Topic 的先修关系继续唯一使用现有 `TopicDependency`，不重复建模。
- Attachment 经过迁移后允许安全绑定 Resource；继续校验扩展名、MIME 魔数、大小、SHA 和父对象权限。
- 新实体首版标为 online-only；离线同步必须进入单独的 sync-v2/能力协商设计。
- 搜索优先使用 PostgreSQL 有界词法检索、标题/引用键权重和图邻居扩展；在固定黄金集不达标前不引入向量库。

### P0：AI 分析与人工确认闭环

目标：允许 AI 异步分析用户明确授权的内容，同时保证模型不能直接写入正式知识库。

- 复用现有 AI Gateway 的 Provider、Model、Task Route、预算、加密输入、Run、Draft、候选回退和人工接受/拒绝能力，不另建第二套 AI 平台。
- 增加 `knowledge.topic_extract`、`knowledge.edge_suggest`、`knowledge.quiz_draft` 和 `knowledge.answer_with_citations` 等受控任务类型。
- 每次发送前显示 Provider、模型、字段、摘录数量、Token/费用预估和是否保留输入；只发送用户勾选并确认的摘录，不默认发送整份私有文档。
- AI 输出必须通过固定 JSON Schema、字段长度、引用存在性、对象权限、内容哈希和目标版本校验后才能成为候选。
- AI 候选在图谱中以虚线显示；用户可以编辑、接受或拒绝。只有接受动作触发领域服务在同一事务内写入正式知识和审计记录。
- 使用来源哈希、处理器版本、Prompt 版本和目标版本生成幂等键；重复分析不能创建重复正式记录。
- 外部请求结果不确定时不得自动重放，避免重复计费；候选连续被拒绝后按候选哈希限期降权，但不得影响其他用户。
- 多模型按任务路由使用一个主模型和至多一个可选复核模型；禁止默认把同一私有内容依次发送给所有 Provider。
- 首批兼容性与质量评测候选为 GLM-5.2（中文结构化候选）、Kimi K3（资料纲要与有限片段综合）、DeepSeek V4（矛盾与引用充分性复核）和 GPT-5.6（用户显式选择的高质量综合）；这些角色必须通过真实 API、隐私条款、结构化输出和费用基准后才可启用，不能把订阅套餐等同于 API 额度，也不能在领域代码中硬编码模型品牌。

### P0：动态图谱与自适应学习

- 图谱节点覆盖 Source、Excerpt、Topic、Quiz 和 Claim；边覆盖来源、定义、支持、反驳、示例、派生和先修。
- 由浏览器执行图布局；服务端只返回当前根节点的一至两跳有界子图。默认最多显示 150 个节点、400 条边，超出后聚类并按需展开。
- 人工确认关系使用实线，AI 候选使用虚线；边详情必须展示来源摘录、页码/章节、创建者、状态和时间。
- 考、学、研、导共享同一图谱数据和引擎，只改变默认节点类型、筛选器、布局和建议动作。
- 移动端提供等价的列表/树视图，不能把复杂画布作为唯一操作方式。
- 根据 QuizAttempt、信心、耗时、ErrorPattern 和 ReviewSchedule 透明更新建议掌握度与复习优先级；正式确认和计划修改仍由用户完成。

### P1：洞察与离线连续性

- 周复盘从真实任务、会话、证据、复习和阻塞生成可编辑摘要，不自动评价用户。
- 目标→任务→笔记→证据→知识点→研究声明支持双向跳转和来源追踪。
- Today、Records、Review 支持受保护应用壳离线冷启动。
- 明确页面级 Offline Read / Offline Write / Queue / Online-only 能力矩阵。
- Outbox 和附件队列提供预计恢复动作、最后成功时间和失败分类。
- 建议下一步规则透明、可关闭，只提出候选动作，不直接修改计划或掌握度。

### 零新增云成本运行边界

- 阿里云 2C2G 继续作为唯一 Production，只运行现有 Web、API、Worker、PostgreSQL、Redis、反向代理和备份；不新增常驻图数据库、向量库、OCR、Embedding 或本地模型容器。
- 火山云 2C2G 继续作为 Staging 和冷恢复目标，不做跨云双活或生产数据库直连。
- Windows 本地节点承担可中断、单并发的 PDF 解析、OCR、Embedding 和知识候选任务；只通过出站 HTTPS 和短期最小权限租约访问云端，离线时不得影响网站核心流程。
- Windows 处理窗口为约 08:00–10:00、20:00–22:00，实际运行不承诺自然日 SLA；距窗口结束 20 分钟停止领取新任务并写入阶段检查点。
- 本地明文、模型缓存和待上传结果必须进入专用加密工作区。当前设备所有卷未启用 BitLocker，因此启用本地知识 Worker 前必须先完成 BitLocker 或等价加密方案。
- 8GB Mac 主要承担 Safari/WebKit、移动布局与轻量文本提取，不作为生产常驻节点。
- Beta 默认最多 5 名知识库用户、2–3 名同时活跃用户、单文件 20MB、单文档 300 页、全站云端附件 500MB；达到容量停止线后暂停摄入而不是放宽安全限制。

成功指标：

- 100% AI 节点、关系和卡片先进入 Draft/Suggested；未经用户接受直接成为正式知识的数量为 0；
- 100% 已接受 AI 关系可以回到具体摘录和页码/章节，孤儿引用为 0；
- 接受关系后当前图谱在 300ms 内增量更新，移动端可完成同等审核操作；
- 固定黄金集词法检索 Recall@10 达到 85% 时不批准向量扩张；低于门槛才进入 v0.2.1 语义检索评估；
- 同一资料版本和用户事件序列可确定性重放，用户 A 的反馈不改变用户 B 的状态；
- 断网冷启动后 3 秒内可看到最近一次可信本地状态，重新联网后 95% 普通 Outbox 在 60 秒内收敛；
- 单知识任务并发为 1 时，核心 API P95 回归小于 20%、没有 OOM，周复盘和图谱中的每个数字可追溯到原始记录。

## v0.2.1：本地解析与论文证据工作台

### 必做能力

- DOI、标题或公开 URL 查询 Crossref/OpenAlex 等公开元数据；遵守条款、缓存和速率限制。
- 用户合法提供 PDF 后建立页码定位、批注、引用摘录和阅读进度。
- 论文记录与研究问题、声明、支持/反证/不确定证据连接。
- 引用导出继续使用开放 BibTeX；保留来源和人工修正。
- AI 伴读只处理用户明确选择的片段，输出摘要、问题、术语解释和证据对照草稿，并带页码来源。
- Windows 本地 Worker 以阶段检查点完成 PDF 文本层提取、可选 OCR、分块、去重和候选生成；不得持有生产数据库凭据或开放公网入站端口。
- 只有 v0.2.0 固定黄金集的词法检索低于门槛时，才评估小型 Embedding 与 pgvector；Embedding 由本地设备或用户批准的 Provider 生成，不在 2C2G Production 上运行模型。
- 自然语言问答只从用户选择或检索命中的有限摘录构建上下文，每个事实句必须给出可点击来源或明确说明证据不足。

### 不做边界

- 不抓取付费墙正文；
- 不自动把整份私有 PDF 发送给 AI Provider；
- 不自动判定论文质量、研究结论或引用真实性；
- 不部署 Neo4j、Qdrant、Milvus、Elasticsearch 或完整 GraphRAG；
- 不把本地 Windows/Mac 作为登录、同步、复习或在线查询的强依赖；
- 外部元数据失败时保留手工录入路径。

成功指标：

- 90% 引用摘录可从声明反向定位到论文页码；
- AI 草稿的每条事实性引用都带来源片段或明确标注“无来源”；
- PDF/引用数据离线与同步边界通过独立威胁模型。

## v0.3.0：个人移动端候选

- Android：TWA + Digital Asset Links + 独立签名 keystore；
- iOS：App-bound WKWebView，无通用 JavaScript 原生桥；
- HarmonyOS：ArkUI Web 薄壳，无账号/Token/恢复密钥内置；
- 实体设备覆盖登录、onboarding、Vault、软键盘、附件选择、弱网、恢复和会话撤销；
- 安装包只通过受保护签名流程产生，附 SBOM、哈希和恶意软件扫描结果。

成功指标：三端核心闭环无 P0/P1 真机缺陷；签名材料不进入仓库、日志或公共 Release；弱网恢复不产生重复正式记录。

## v0.4.0：Connector/Automation v2（独立架构任务）

### 先设计再编码

- Connector Credential Vault：独立密钥、版本、轮换、撤销、最小 scope 和不可回显。
- OAuth/账号连接：state/PKCE、回调 Origin、供应商条款、Token 生命周期和断连传播。
- Webhook：签名、重放保护、幂等键、入站大小限制、出站退避和死信。
- MCP/API Token：能力授权、到期、轮换、撤销、审计和速率限制。
- Automation：触发器/条件/执行器、草稿与启用分离、dry-run、人工确认点、运行历史和回滚补偿。

### 产品原则

- 自动化默认关闭，创建规则不等于启用；
- 涉及正式验收、掌握度、研究结论、成员权限、分享和外部发送时必须人工确认；
- 每次外部读取/写入都显示来源、范围和最近结果；
- 连接器失败不能阻塞本地学习闭环。

进入条件：v0.1.1 worker 与 E2E P0 实现已关闭并完成稳定性观察；凭据/自动化 ADR 和威胁模型批准；数据迁移与回滚方案完成。

## 版本统一门禁

1. 产品：真实用户动作、空/错/加载/权限状态和成功指标明确；
2. 数据：迁移前向/回退或明确无迁移，备份恢复演练通过；
3. 安全：威胁模型、日志去敏、密钥和外部数据范围通过审查；
4. 离线/同步：Outbox、冲突、旧客户端、Bootstrap 与恢复语义不回归；
5. 质量：单元、PostgreSQL/Redis 集成、契约、认证浏览器和关键视觉门禁全绿；
6. 运维：健康、指标、告警、容量和回滚点可执行；
7. 发布：候选镜像按 digest 固定，SBOM/漏洞/许可证/签名验证通过，Production 仍需人工批准。

## 现在不应做的事

- 不增加新的一级导航工作台；
- 不把示例数字、连接状态或 AI 生成内容写成真实成果；
- 不在 worker 可观测性和 E2E 可信度修复前上线复杂自动化；
- 不为了“移动端”复制服务端权限、同步或数据模型；
- 不让 AI、自动化或本地 Worker 绕过 Draft/Suggested 状态直接写正式知识；
- 不通过全局切换 Provider 的方式并行运行多个开发 Agent；每个任务必须固定模型、Provider、分支和输入范围；
- 不把自动化测试通过替代实体设备、恢复演练和生产观察。
