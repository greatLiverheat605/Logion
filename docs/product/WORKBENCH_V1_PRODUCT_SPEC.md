# Logion Workbench v1 产品规格

> 状态：产品基线已批准；领域持久化和正式施工待审批
>
> 日期：2026-08-17（Asia/Shanghai）
>
> 关联：[ADR-0030](../adr/0030-workbench-v1.md)、[产品重构执行计划](./PRODUCT_REDESIGN_EXECUTION_PLAN.md)

## 1. 产品目标

把现有“考、学、研、导、自定义画像”升级为成熟工作台系统：同一账户可以用不同工作方式处理同一批已授权对象，固定工作台提供可靠领域流程，自定义工作台提供受控组织能力，任何切换都不改变权限、数据归属或正式对象事实源。

成功后的用户心智：

```text
工作区决定我和谁协作
知识库决定数据放在哪里、谁能看
工作台决定我现在怎样完成任务
项目决定我正在推进哪件具体事情
Today 决定今天先做什么
```

## 2. 已冻结产品决定

| ID  | 决定                         | 产品含义                                     |
| --- | ---------------------------- | -------------------------------------------- |
| W1  | 主界面使用“工作台”           | “画像”只用于旧设置兼容和首次引导迁移         |
| W2  | 四个固定工作台各一个         | 多个课题、考试和学习目标由工作台内项目承载   |
| W3  | 自定义支持复制模板或空白创建 | 默认推荐从最接近的固定模板开始               |
| W4  | 自定义属性属于工作台上下文   | 不覆盖正式对象字段、状态或权限               |
| W5  | 每个工作台可设默认知识库     | 可以引用其他已授权知识库，不自动扩权         |
| W6  | 统一 Shell + 不同工作表面    | 不建设四套主题、反馈、导航和响应式系统       |
| W7  | Today 始终统一               | 工作台只为 Today 提供候选行动和来源标签      |
| W8  | 导师工作台不授予权限         | 只聚合服务端已授权的 Shared Space 和成员数据 |

旧规划中“Today 允许四画像明显不同布局”的表述由 W7 替代。Today 可以按活动来源调整信息权重，但结构和行动合同保持一致。

## 3. 概念与边界

| 概念                   | 负责什么                                 | 不负责什么                    |
| ---------------------- | ---------------------------------------- | ----------------------------- |
| Workspace Role         | Owner/Editor/Viewer 等治理权限           | 不决定用户当前工作方式        |
| Knowledge Base / Space | 数据范围、Private/Shared 与授权          | 不决定首页模块和默认流程      |
| Workbench              | 对授权对象的模块、布局、筛选和任务化投影 | 不是权限边界或第二份数据库    |
| Project/Context        | 具体学习、研究或考试上下文               | 不创建新的应用一级区域        |
| Persona legacy         | 旧名称、路由偏好和迁移来源               | 不能继续承载完整 Workbench v1 |

## 4. 共享核心与领域对象

### 4.1 共享核心

Task、Source/Resource、Excerpt、Topic、Note、Evidence、Session、Review、Citation、History 等对象可服务多个工作台。它们保持一个正式记录，可由不同工作台引用。

### 4.2 固定工作台

| 工作台 | 专属对象链                                                                   | 首要问题                                 | 主行动来源                               | 核心视图                               |
| ------ | ---------------------------------------------------------------------------- | ---------------------------------------- | ---------------------------------------- | -------------------------------------- |
| 学习   | Goal → Track → StudyProject → Task/Session → Deliverable → Mastery           | 如何把资料转为连续进展和成果             | 当前项目下一里程碑、到期复习、待验收成果 | 项目桌面、路线时间轴、成果账本、掌握图 |
| 研究   | Question → Source/Excerpt → Claim → Evidence → Experiment → Finding → Output | 当前结论由什么支持，还缺什么证据         | 待核验声明、来源冲突、实验阻塞、反馈     | 来源/编辑/证据三栏、证据图、实验轨迹   |
| 考试   | Exam → Subject → Syllabus → MockExam → Score → ReviewSchedule                | 今天学什么、薄弱范围在哪里、进步是否真实 | 到期复习、大纲缺口、下一模考、错因       | 倒计时、覆盖矩阵、成绩趋势、复习队列   |
| 导师   | Shared Space → Member → Rubric → Review → Feedback → Finding → Audit         | 什么需要审阅，是否在授权范围内           | 待审对象、未处理反馈、开放发现           | 审阅队列、对比批注、Rubric、审计时间线 |

固定工作台的差异必须来自真实领域对象和任务顺序。不得用同一组“阶段覆盖/证据就绪/待验收”示例数字替代四种数据模型。

## 5. Today 与 Workbench

Today 只有一个稳定合同：

```text
Now：唯一建议行动
Why：为什么今天出现
Evidence：完成需要什么证据
Acceptance：谁/什么规则负责验收
Next：最多三个后续行动
```

工作台可以向 Today 提供候选，但 Today 统一排序并显示来源：

- `研究 · 核验声明 C-12`
- `考试 · 完成到期复习`
- `学习 · 提交项目成果`
- `导师 · 审阅共享报告`

完成会话不等于完成任务，提交证据不等于验收通过。切换工作台不能取消、重建或重排已经持久化的命令结果。

## 6. 固定工作台体验

### 6.1 学习：项目桌面

- 首屏显示当前项目、下一里程碑、最近成果和到期复习；
- 路线视图表达目标、阶段与依赖，不用装饰进度环；
- 成果必须可返回 Task、Session、Evidence 和验收；
- 视觉保持安静，主要签名是“路线 → 项目 → 成果”的连续轨道。

### 6.2 研究：证据实验台

- 研究问题固定为当前上下文锚点；
- Source/Excerpt、Claim/Evidence、Experiment/Finding 在同一工作表面可回跳；
- 图谱区分正式、候选、争议和拒绝，并使用文字标签；
- 科技感来自版本、关系、运行和指标变化，不来自霓虹、粒子或伪实时数字；
- DOI、对象 ID、版本和指标允许使用等宽字体，正文仍保持高可读中文字体。

### 6.3 考试：覆盖指挥台

- 日期和范围是真实用户记录，不预设考试；
- 科目/大纲覆盖矩阵直接连接复习和模考；
- 成绩趋势必须标注来源、时间和样本，不预测不存在的数据；
- 红色只用于全局危险/错误，薄弱项使用受控警示和文字，不制造焦虑主题。

### 6.4 导师：授权审阅台

- 只读取 Shared Space 和当前角色允许的成员信息；
- 私有 Space 不进入计数，权限不足不泄露对象存在性；
- 审阅使用队列、对比、Rubric、批注和审计时间线；
- 工作台低动效、强调稳定和可复核，不使用团队排名或成员绩效排行。

## 7. 自定义工作台

### 7.1 创建流程

1. 选择“复制学习/研究/考试/导师模板”或“空白工作台”；
2. 设置名称、图标、说明和受控辅助色；
3. 选择默认知识库和可见模块；
4. 配置默认视图、筛选和快捷创建；
5. 可选增加有限属性；
6. 预览桌面/移动和权限范围；
7. 保存后进入工作台，正式对象不被复制。

### 7.2 允许模块

首批模块从已注册目录选择：Next Action、Task Queue、Projects、Sources、Topics、Review、Evidence、Timeline、Graph Projection、Saved View、Recent Objects、Pinned Objects。模块没有任意代码执行能力。

### 7.3 有限属性

允许文本、数字、日期、单选、多选、布尔、URL、评分和对象引用。属性值默认附着在工作台对象引用上，只用于当前工作台展示、筛选和排序。

示例：同一个 Source 在研究工作台中可标记“证据强度”，在学习工作台中可标记“阅读优先级”；Source 的正式标题、版本、Space 和授权保持一份。

### 7.4 生命周期

- 固定工作台：可隐藏、不可删除；
- 自定义工作台：可重命名、复制、导出、归档和删除配置；
- 删除自定义工作台先显示引用数量和影响，默认只删除配置与引用；
- 正式对象删除必须进入独立影响确认；
- 配置升级失败时回退到安全模板，不静默清空。

## 8. 跨工作台对象行为

| 命令             | 结果                                             |
| ---------------- | ------------------------------------------------ |
| 添加到其他工作台 | 创建引用，不复制正式对象                         |
| 从当前工作台移除 | 删除当前引用，正式对象仍存在                     |
| 移动主要上下文   | 更新主要负责项目/工作台；需要版本和影响确认      |
| 移动到其他知识库 | 跨 Space 操作，重新授权并按现有移动/复制合同处理 |
| 删除正式对象     | 展示所有可见引用影响，执行正式删除合同           |

失去任一 Space 权限后，引用必须失败关闭。UI 不得用“引用仍存在”泄露无权对象。

## 9. 信息架构

五区保持不变：今天、工作台、知识库、协作空间、系统中心。

- 工作台区域顶部提供当前工作台切换器，但不在全站重复一排五个大标签；
- 全局搜索、通知、快速捕获、最近对象和命令面板属于 Shell；
- Knowledge Graph 只有一个引擎，工作台使用不同默认投影；
- `/app/today` 保持统一；现有深链接保留并继续受认证/服务端权限保护；
- 自定义工作台不产生新的一级导航区域。

## 10. 视觉语义

统一：石墨中性表面、矿物青绿品牌主色、Light/Dark、4px 网格、4/6/8px 圆角、边框优先、Lucide 风格线性图标、相同反馈和焦点系统。

差异只发生在工作表面：

| 工作台 | 布局签名     | 数据表达                     | 动效                           |
| ------ | ------------ | ---------------------------- | ------------------------------ |
| 学习   | 连续项目轨道 | 路线、成果、掌握             | 里程碑和成果状态轻量过渡       |
| 研究   | 证据实验台   | 关系、版本、实验轨迹         | 布局收敛、选中证据链、运行状态 |
| 考试   | 覆盖指挥台   | 大纲矩阵、成绩趋势、到期队列 | 只在范围/队列更新时过渡        |
| 导师   | 审阅台       | 对比、Rubric、批注、审计     | 最少动效，强调稳定             |
| 自定义 | 受控模块画布 | 由已注册模块决定             | 继承模块合同                   |

工作台辅助色不能代替成功、警告、危险、权限、正式关系或 AI Draft 语义。

## 11. 完整状态

每个固定工作台和自定义创建器至少覆盖：loading、empty、ready、saving、success、error、offline、locked、permission denied、409 conflict、disabled capability、stale data、AI Draft、graph truncated。所有数字显示真实来源、时间范围和陈旧状态。

## 12. 成功指标

- 进入任一工作台 10 秒内能说出当前项目、下一行动和完成证据；
- 四种固定工作台的首要任务路径明显不同，不能仅靠颜色判断；
- 切换工作台不改变 Workspace/Space/Role 和正式对象数量；
- 自定义工作台可在 3 分钟内从模板创建并完成首次保存；
- 100% 跨工作台操作区分引用、主要上下文、跨 Space 和正式删除；
- 320/390/1024/1440、Light/Dark、键盘、axe 和 reduced-motion 全绿；
- 409、离线、权限和配置失效均不静默丢失用户设置。

## 13. 分阶段实现建议

1. **W0 合同与原型**：ADR、Schema 草案、完整隔离原型和产品审批；
2. **W1 兼容适配**：旧 Persona 只读适配、统一 Today、工作台术语和固定模板入口；
3. **W2 固定工作台**：四种领域布局和真实对象投影；
4. **W3 偏好持久化**：版本化配置、默认知识库、布局恢复和 409；
5. **W4 自定义定义**：受控模块、视图、筛选和创建器；
6. **W5 对象引用与有限属性**：独立迁移/API/权限后启用；
7. **W6 真实验收**：认证浏览器、跨 Space、冲突、响应式、无障碍和回滚。

W0 合同与隔离原型已获产品 Owner 批准；进入 W1 或修改正式前端仍需新的明确施工授权。对象引用/有限属性的迁移与 OpenAPI 未批准前，不进入 W5。
