# ADR-0029：自适应知识空间与人工验收边界

- 状态：Accepted
- 日期：2026-08-05
- 范围：v0.2.0 设计基线
- 相关决策：[ADR-0002](0002-browser-authentication-and-session-boundary.md)、[ADR-0003](0003-offline-sync-protocol.md)、[ADR-0004](0004-workspace-space-permission-model.md)、[ADR-0013](0013-ai-provider-credential-boundary.md)、[ADR-0015](0015-ai-routing-and-budget-policy.md)、[ADR-0016](0016-durable-ai-run-and-draft-boundary.md)、[ADR-0021](0021-recoverable-account-deletion.md)

## 背景

v0.2.0 要把来源、用户选定摘录、正式知识、AI 候选和复习连接成可追溯闭环，同时保持现有租户、权限、认证、AI Gateway 和同步边界。路线图已经批准复用 `Space`、首版 online-only、显式引用外键、人工接受以及零新增常驻云服务；本 ADR 固化足以拆分实现和安全审查的边界，不批准迁移、OpenAPI 或具体 UI。2026-08-05 的 M0 产品决策接受本 ADR，并冻结下述首版边界；迁移、合同与生产写入仍由后续门禁单独授权。

## 决策

### 1. 知识空间继续是 Space

- 不新增与 `Space` 平行的顶层 KnowledgeBase。每个新知识记录都由 `workspace_id + space_id` 定界，查询从该范围和认证主体开始。
- Private Space 仍只允许 owner 访问正文；Workspace Owner/Admin 不因此获得读取权。共享、移动或复制到 Shared Space 继续是显式披露操作，沿用现有最近认证、影响预览、命名 permission 和审计语义。
- 当前认证/会话边界不变；离线 PIN 或设备密钥不是在线身份。AI Gateway 继续唯一拥有 Provider、模型路由、预算、运行、加密输入和草稿。
- 新能力嵌入 Today、Review、Records 及既有领域工作台的投影视图，不增加一级导航目的地。

### 2. SourceExcerpt 是证据快照，不是任意文本

`SourceExcerpt` 表示用户明确选择并允许持久化的最小来源片段。它必须：

- 具有 Workspace/Space 范围、创建者、乐观 `version`、创建/更新时间和可删除状态；
- 指向同范围且当前主体可读的现有 `Resource`；首版不新增与 `Resource` 平行的通用 Source 记录，来源专有元数据由 V20-01 在 `Resource` 关联边界内设计；
- 保存有界摘录文本、稳定定位（页码、章节和/或字符区间）、来源版本标识、规范内容哈希及哈希算法/规范化版本；
- 区分来源文件哈希、来源版本哈希与摘录内容哈希，禁止把哈希当作授权凭证；
- 在创建和读取时重新校验来源及 Space 权限。来源后续变化不会静默改写摘录；而是产生新版本或标记 stale，保留可审计差异。

PDF 原件首版默认留在本地。云端只接收路线图允许的来源元数据、哈希、定位、用户选定摘录及已批准关系，不得默认上传整份私有文档。

### 3. KnowledgeCitation 是受约束的证据连接

`KnowledgeCitation` 从一个同范围 `SourceExcerpt` 指向且只指向一个正式目标：`Topic`、`QuizItem`、`ResearchClaim` 或 `Note`。

- 关系使用四个显式、可空的 typed target foreign key 集合，并以数据库 CHECK 约束非空目标数恰好为一；不得使用无约束 `target_type + target_id` 或 JSON 多态引用。
- 每个目标外键必须包含目标已有的租户/Space（及 ResearchClaim 所需个人所有者）范围，使跨 Workspace、跨 Space、跨个人所有者连接在数据库层失败。迁移必须先补齐相应组合唯一键，再建立约束。
- 引用本身记录创建者、版本、创建时间、状态和由哪次人工接受产生；读取引用必须同时有权读取 excerpt 和 target，任何一端失权都失败关闭。
- 删除或移动任一端不得留下可见孤儿引用。软删除、级联、保留墓碑及共享贡献保留的具体组合须在删除/隐私评审中决定，并用恢复演练证明。
- Topic 之间的先修关系仍唯一使用现有 `TopicDependency`。`KnowledgeCitation` 不表达先修，也不创建第二套 Topic-to-Topic 边。

“支持、反驳、定义、示例、派生”等图谱展示语义需要单独的受控关系字段或既有领域关系映射；其枚举、方向和去重规则属于 OpenAPI/迁移前设计门，不能借 citation target 类型推断。无论展示关系如何设计，`TopicDependency` 始终是唯一 Topic 先修关系。

### 4. AI 只能产生 Draft/Suggested

- 所有 AI 生成的节点、边、试题、摘要、答案和掌握度都先进入现有 `AIRun` / `AIOutputDraft` 或经批准的 Suggested 边界，永不直接写正式知识。
- 任务创建前显示 Provider、模型、字段、摘录数量、Token/费用估算和输入保留策略；服务端只解析用户勾选的 excerpt，并再次校验权限、哈希和长度。默认不得发送整份私有文档或把同一内容依次发送给所有 Provider。
- Provider 输出先通过固定 JSON Schema、响应/字段上限、引用存在性、目标范围、内容哈希和目标版本校验。模型提供的 ID、引用、HTML、Markdown 和指令都按不可信数据处理。
- ADR-0016 的 `accepted` 仅表示草稿决策，仍不表示正式对象已更新。v0.2.0 的领域 apply 服务必须执行独立的用户接受事务：锁定 draft 与目标、重新授权、比较 excerpt 哈希和目标/draft 版本、校验引用完整性，然后在同一 PostgreSQL 事务中写正式知识、typed citation、幂等收据和最小审计证据。
- 编辑后接受必须审计“原候选摘要 + 用户最终变更摘要”，但不得把敏感正文写入审计或日志。拒绝和过期候选不影响正式知识或其他用户状态。
- 自适应学习只生成可解释、可关闭的建议掌握度和复习优先级；正式掌握确认及计划修改仍由用户完成，不进行基础模型持续训练或微调。

### 5. 并发、幂等与外部请求不确定性

- 所有可变知识记录使用乐观版本。更新、删除、接受和移动要求客户端提供期望版本；版本不匹配返回稳定冲突，不自动合并安全敏感或正式关系。
- 分析幂等键至少绑定用户、Workspace/Space、任务类型、选定 excerpt 的有序哈希集合、来源版本、处理器版本、Prompt 版本和目标版本。接受幂等键还绑定 draft、最终规范化负载及目标版本。
- 相同键与相同负载返回原运行/收据；相同键但不同负载失败。数据库唯一约束和事务是最终防重边界，客户端防抖不是证据。
- Provider 不支持幂等且外部响应是否完成不确定时，不得自动重放 running 请求。运行进入人工可审查的不确定状态，预算账本区分预占、可归因消费和未知外部费用，避免重复计费。
- Worker 重试、崩溃恢复和用户重复点击不得重复创建正式对象、引用、审计或收费副作用。

### 6. 查询、图与呈现边界

- 服务端只返回授权根节点的一至两跳有界子图；默认上限为 150 节点、400 边，并同时限制深度、时间、行数、响应字节、排序/过滤复杂度和每主体速率。超限返回截断标记及安全游标，不做无界递归。
- 首版检索使用 PostgreSQL 有界词法检索、标题/引用键权重及受限邻居扩展。在固定黄金集 Recall@10 未低于路线图门槛前，不批准向量库；向量/语义检索属于后续决策。
- 浏览器负责布局，但服务端决定授权和边界。移动端必须有等价列表/树审核路径，画布不是唯一操作方式。
- 摘录、AI 文本和来源元数据按不可信内容呈现：默认纯文本；确需富文本时使用统一消毒器、严格 URL 协议和 CSP，禁止内联脚本、事件属性及未经批准的远程内容。

### 7. 附件、删除、保留与日志

- Attachment 绑定 `Resource` 前必须有单独迁移评审。继续执行 init/content/complete、大小、扩展名、声明 MIME、魔数、SHA-256、生成存储键、父对象权限、`nosniff` 和 attachment 下载；不得依据客户端 filename 或 MIME 信任文件。
- 未完成、失败、恶意或孤立上传需要配额占用、隔离和可审计清理；生产不渲染、不执行上传内容。恶意软件/CDR 能力若未实现，必须在产品风险中明确而非宣称安全扫描已通过。
- 账户删除沿用 ADR-0021 的立即撤权、宽限期和去标识化流程。私有 excerpt、citation、draft、缓存和本地任务材料进入同一清理清单；共享贡献、审计和备份的保留期限需法律/隐私负责人批准。该签核完成前，共享知识写入保持关闭。
- 日志、指标和审计不得记录摘录正文、Prompt、模型响应、文件名、来源 URL 查询、哈希全值、Provider 凭据或本地路径。只允许稳定错误码、阶段、计数、耗时、截断/哈希化关联 ID 及最小接受证据。

### 8. Online-only 与本地 Worker

- `SourceExcerpt`、`KnowledgeCitation` 及 v0.2.0 新知识实体首版全部 online-only；不加入 sync-v1 operation、向量、bootstrap、IndexedDB/Vault schema 或兼容矩阵，sync-v1 wire behavior 与校验向量保持不变。
- offline UI 必须明确显示只读缓存/不可用状态，不能把失败写入旧 Outbox。sync-v2 和能力协商需要独立 ADR、威胁模型、协议版本、迁移与双版本测试。
- Windows 本地知识 Worker 只能使用出站 HTTPS 和短期最小权限租约，且不能成为网站核心流程依赖。任何明文、模型缓存、检查点和待上传结果必须位于专用加密工作区。
- 当前设备卷未满足该前提；BitLocker 或等价、可验证的静态加密及密钥恢复方案完成前，本地知识 Worker 必须保持禁用。

## 迁移与回滚边界

本 ADR 不授权迁移。实施时必须单独审查增量、可降级迁移和 OpenAPI 加法变更，并满足：

1. 先增加表、组合唯一键、CHECK/FK、索引和禁用的能力开关；后部署只读路径，再部署写入/接受路径。
2. 外键与 CHECK 必须在生产写路径开启前验证；无法证明范围完整性时停止，不以应用校验替代数据库约束。
3. 回滚检查点分别位于迁移前备份、schema-only 后、只读上线后、首个正式接受前。首个生产知识写入后，代码回滚只能禁用能力并前向修复，不能删除表或丢弃审计/引用。
4. OpenAPI 生成快照必须只含经批准的加法变化；任何 auth、Space permission 或 sync-v1 差异都是停止条件。

## 开放决策

- `Resource` 关联的来源元数据形状，以及 typed citation 的准确 DDL、关系语义枚举、目标移动/复制规则及组合唯一键形状。
- 摘录规范化、哈希算法版本、定位格式、最大长度及来源变化后的 stale 生命周期。
- 新命名 permissions、接受审计最小字段、共享贡献/备份/本地缓存保留期限。
- API 路径、错误码、分页游标、ETag/版本表达和能力开关名称。
- 本地租约、加密工作区证明、检查点格式与远程失联撤销协议；这些需独立安全设计。
- sync-v2/capability negotiation、语义检索/向量及 v0.2.1 PDF 解析能力。

## 后果

- 正式知识有可验证的用户接受、版本和来源证据，AI 或重放不能越过领域事务。
- 新知识首版需要在线连接；现有离线数据仍由 sync-v1 工作，协议不扩大。
- 显式目标外键增加迁移与查询复杂度，但把租户隔离、目标完整性和孤儿防护放到数据库权威边界。
- ADR 已获 M0 接受，但迁移、OpenAPI、权限名、保留政策、共享写入和本地 Worker 仍需后续批准；`Accepted` 只冻结架构边界，不等于实现、上线或生产数据写入授权。
