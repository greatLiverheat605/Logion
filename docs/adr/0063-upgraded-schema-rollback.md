# ADR-0063：新 schema 上的旧应用回滚准备

- 状态：准备方案 A；所有者指定先准备 A，最终 A/B 选择、Claude 复核及上线仍待。
- 日期：2026-09-29
- 依据：v0.3 剩余施工说明 R5；ADR-0013、0019、0023、0031、0041。

## 边界

方案 A 从 0.2.4-rc1 的 `fdadebcfe76a341e3915b3c8cb000f280fbe4fb0` 建独立补丁分支。
补丁不合入 main、不部署；仅用于已经升级的 v0.3 schema，不能在旧 schema 上启动。
数据库不降级、不改写 alembic_version，不删除或回填覆盖已有研究数据。原旧版本制品继续保留。
正式采用 A 必须核对独立兼容证明中的补丁 SHA、实际 schema 来源 SHA、迁移 head 与镜像摘要。
V1–V3 产生后续加法迁移后，须对最终 schema 重新运行兼容证明。

## 最小兼容补丁

旧 Resource、Note、Topic、QuizItem、Task 映射增加可空 research_owner_id，只为过滤私人记录。
旧读取、写入、搜索、配额、导出、附件关联、知识引用、复习派生记录，以及同步快照、增量、
墓碑、版本与冲突均使用相同排除规则。资源约束已保证新类型必有 owner，旧 DTO 继续只看
link/pdf_index；不伪装新类型，不把私人资源暴露给旧客户端。归档、删除空间继续不可读写。
旧论文创建仍在同一事务中生成私人资源映射，避免恢复前向版本后遗漏回滚期间新建的论文。

旧 Worker 每次外呼前拒绝研究上下文、研究任务与私人想法类型，旧界面也不列出或接受研究 AI 草稿。
研究队列保持原数据等待前向版本，不由旧执行器生成错误格式的产物。旧格式导出继续可用，
研究格式导出及其加密制品不由旧 API 提供。凭据加密、会话、Origin、CSRF、网络/TLS 与预算规则不放宽。

回滚期间暂停账户物理清理。旧清理程序不知道完整新数据图，且删除附件文件早于 SQL 提交，
不能依赖外键失败来保护原文件。待处理删除请求和文件全部保留，须恢复经验证的前向版本后
按原政策处理；不扩大旧程序对新表的删除能力，不更改恢复期限或绕过本人确认。
该暂停是方案 A 的明确限制，不能把它描述成全功能旧版或正常长期运行方式。

## 验证与替代方案

用新版本迁移隔离数据库，再由补丁真实 API/Worker 执行旧合同、跨成员隐私、读写/同步/导出、
拒绝研究队列外呼和文件保全测试。对接近生产规模的合成旧数据核对旧列摘要和行数；
旧 paper_records 派生资源单独计数。验证不得使用真实凭据或生产数据。

方案 B 保持新 schema 和当前应用，只做新的前向修复候选；可以关闭研究与 Agent 开关，
保留全部数据及旧客户端恢复入口。A/B 都须保留候选证据、备份及版本，任何生产操作另行批准。
