## 1. 目的与边界

本文件是 Workbench v1 正式前端施工前的 I1 覆盖合同，不是实现完成声明。它盘点现有路由、页面、操作、状态、视口和权限，并记录后续迁移必须保持的回归边界。

批准的产品范围固定为：

- Today 始终统一；
- 固定工作台为学习、研究、考试、导师；
- 支持受控自定义工作台，但自定义范围只能来自已注册模块、顺序、密度和有限视觉配置；
- 工作台只是已授权对象的界面投影，不是新的权限域、数据副本或对象所有权边界；
- 不改变 Workspace Role、Space ACL、`SessionBoundary`、正式对象归属或数据共享语义；
- 同一正式对象可被多个工作台引用，工作台切换不得复制对象或提升权限。

I1 只允许盘点和只读适配设计。本文件不批准新增 API、数据库表、迁移、OpenAPI 字段或生产能力，也不批准打开 Shared Write、Deletion、Attachment、Local Worker、Provider、sync-v1 或 AI Acceptance。

### 2.1 状态图例

矩阵中的状态是验收责任，不表示现有实现已经通过。状态画像展开如下：

- `M`：该画像必须覆盖并形成可恢复闭环；
- `C`：仅在对应合同、上下文或能力存在时覆盖；
- `N`：不适用，不得伪造该状态；
- `saving` 对应命令 `pending`；网络失败只有真实写入 Outbox 后才能称为 `offline_queued`，否则必须显示 `offline` 或 `error`。

### 2.2 权限图例

| 缩写        | 含义                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------- |
| `PUB`       | 无会话公开页面；仍受令牌、速率限制和输出转义约束                                              |
| `AUTH`      | 有效会话；`/app/**` 还要求完成 onboarding                                                     |
| `ACTIVE`    | 当前用户是目标 Workspace 的 active member                                                     |
| `PO`        | Private Space 的 `owner_user_id` 等于当前用户；不满足时返回不可枚举 404                       |
| `CONTENT:R` | `shared_content.read`；Shared Space 中普通协作内容的读取权限                                  |
| `WS:R/W/A`  | Knowledge Space 专用的 `shared_knowledge.read/write/accept`                                   |
| `PLAN:W`    | `shared_plan.write`                                                                           |
| `EVIDENCE`  | `evidence.submit`                                                                             |
| `REVIEW`    | `review.write`                                                                                |
| `MEMBERS`   | `workspace.manage_members`                                                                    |
| `SECURITY`  | `workspace.manage_security`                                                                   |
| `AI:C/U`    | `ai.configure` / `ai.use`                                                                     |
| `RECENT`    | 敏感命令要求 recent authentication                                                            |
| `FLAG`      | 源码真实存在的 `knowledge_space_*`、Attachment 或 Local Worker 开关；关闭时不得发起伪可用请求 |

角色名称使用 `Owner / Admin / Editor / Contributor / Reviewer / Viewer`。Persona、固定 Workbench 或自定义 Workbench 只控制界面投影和导航可见性，不是上述权限的别名。

### 2.3 视口口径

每个可视页面均必须在 `1440 / 1024 / 390 / 320` CSS px 下验收：无横向溢出、内容不互相遮挡、键盘焦点可见、对话框焦点闭环、移动触控目标至少 44px。还必须覆盖 Light/Dark、`prefers-reduced-motion` 和 axe；320px 不得通过隐藏关键命令来“通过”。

## 8. 权限与数据合同不变量

### 8.1 Session 与 API 客户端

- 所有 `/app/**` 统一经过 `SessionBoundary(requireOnboarding=true) -> PersonaProvider -> VaultSessionProvider -> AppShell`。
- 会话 loading、anonymous、error 和 onboarding gate 必须在页面数据请求前失败关闭。
- 浏览器 API 客户端只允许 `/api/v1/**` 同源路径，使用 same-origin Cookie、`cache: no-store` 和 `redirect: error`。
- 调用方不得手工注入 `Authorization`、`Cookie`、`Origin`、`Referer` 或 `X-CSRF-Token`；写请求通过现有 CSRF Cookie 合同设置 token。
- 服务端错误必须保留规范化 `code`、`request_id`、`retryable` 和 HTTP status；UI 不展示原始响应、堆栈或完整终端日志。

### 8.2 Workspace Role 权限表

### 8.3 Space 与共享语义

- 每次 Workspace 操作先验证 active membership；suspended/revoked/deleted 范围失败关闭。
- Private Space 只有记录的 owner 用户可见；其他用户包括 Workspace Owner/Admin 均使用不可枚举 404。
- Shared Space 先按 scoped query 解析，再按各对象服务的精确 `Permission` 判定；只有 Knowledge Space 写入额外受默认关闭的 `knowledge_space_shared_writes_enabled` 约束，既有 `shared_plan.write` 等合同不得被误写为同一总开关。
- 无权读取 Shared knowledge 使用不可枚举失败；无权写/接受使用明确拒绝但不得泄露额外对象信息。
- 成员管理、邀请、安全、Provider 等命令逐一遵守现有 recent-auth、Origin、CSRF 和速率限制组合；不得把某一操作的边界笼统继承给同页其他操作。
- Workbench 配置只保存引用和显示偏好；删除配置不得删除被引用的正式对象。
