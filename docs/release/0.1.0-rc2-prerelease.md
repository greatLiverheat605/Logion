## 1. 本候选新增内容

- 阿里云邮件推送事务邮件适配器；
- ECS RAM 角色短期凭据，强制 IMDSv2，不支持长期 AccessKey 配置；
- 邮箱验证、密码找回和安全通知的 Worker 投递；
- 有界租约、重试、终态密文清除和去敏事件日志；
- Production 对邮件 Provider、HTTPS Origin、发信地址、RAM 角色和非开发密钥失败关闭；
- Worker 专用公网出方向，API、PostgreSQL 和 Redis 保持内部网络；
- 阿里云域名、邮件、备份、替换、回滚和预发布验收文档。

没有新增 API 路由、OpenAPI 契约或 Alembic 迁移。

## 2. 依赖与安全决策

旧版阿里云 DirectMail SDK 限制 `cryptography <49`，与 Logion 的
`cryptography >=49` 安全基线冲突。本候选不降低加密库，改用：

- 阿里云官方 `alibabacloud-credentials` 获取 ECS RAM 临时凭据；
- Logion 内部实现 ACS3-HMAC-SHA256 签名；
- `httpx` 固定 HTTPS 官方 Endpoint、禁用重定向和系统代理。

该决策需要保留签名固定向量测试、真实投递测试和依赖审计证据。

## 8. 已知边界

- Workspace 邀请 Token 仍通过可信渠道传递，没有邀请邮件模板；
- DirectMail 的发送确认存在极低概率的“Provider 已接收、数据库未标记”崩溃窗口，可能重复
  发送同一封邮件；一次性 Token 仍只允许消费一次；
- Compose 是单机部署，没有高可用；
- PostgreSQL/Redis/附件仍在本机卷，OSS 仅保存加密备份，不是在线附件存储；
- 手机端是响应式 PWA，不是原生 App；
- 2 核 2 GB 仅适合低频封闭使用，资源越线必须升级内存或停止增加用户。

## 9. 晋级与停止条件

预发布环境至少稳定观察 24 小时，并满足：

- 无持续 5xx、OOM、异常重启或邮件积压；
- 登录、核心写入、同步、邮件、备份、恢复和告警全部通过；
- 部署后备份已验证并复制到私有 OSS；
- 没有高严重度安全缺陷或数据损坏。

满足后只能由人工明确批准 Production。观察期内失败则停止晋级，保留数据卷和证据，回滚兼容
应用镜像或前向修复；不得自动回滚数据库或删除卷。
