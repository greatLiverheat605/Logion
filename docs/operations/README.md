# 部署与运维手册

本手册面向自托管管理员，覆盖部署准备、日常维护、升级、备份和故障处理。产品功能与日常操作见[用户手册](../user-guide.md)。

## 1. 选择运行方式

| 用途         | 入口                                                                     | 说明                                  |
| ------------ | ------------------------------------------------------------------------ | ------------------------------------- |
| 本机体验     | [README](../../README.md#本地体验)                                       | 开发配置、回环地址、可丢弃测试数据    |
| 自托管生产   | [生产发布手册](../../infra/runbooks/aliyun-production-release.md)        | HTTPS、受邀注册、独立密钥、不可变镜像 |
| 受限资源测试 | [2 核 2 GB 参考](../../infra/runbooks/aliyun-2c2g-staging-deployment.md) | 需要实际容量验证，不作为通用配置承诺  |

Compose 包含 Web、API、Worker、PostgreSQL、Redis、反向代理和 Backup；`attachment-init` 是一次性初始化服务。配置模板是参考拓扑，不提供高可用保障。

## 2. 首次生产部署

按[生产发布手册](../../infra/runbooks/aliyun-production-release.md)串行执行：

1. 确定完整源码提交和同一提交的通过记录，取得候选 manifest、镜像 digest 与签名证明。
2. 配置 DNS、HTTPS、证书续期和网络边界。
3. 生成并分别托管认证、TOTP、邮件、AI、导出及备份密钥；不得复用示例值。
4. 配置受邀注册、首次 Owner 引导及真实邮件服务。
5. 建立数据库与数据卷，执行对应版本迁移。
6. 启动服务，核对版本、健康状态与资源占用。
7. 完成登录、核心业务、邮件、同步、备份恢复和已启用能力的验收。
8. 设置告警接收人，观察至少 24 小时，满足发布条件后再结束观察。

已有部署升级时保留原密钥与数据卷。不得将全新环境初始化命令直接应用到已有生产数据。

### 功能接入

| 能力                  | 配置与验收                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 邮件                  | [DirectMail 接入](../../infra/runbooks/aliyun-directmail-prerelease.md)；核对实收、失败与退信                            |
| AI                    | 配置凭据加密 keyring、允许的出站网络、Provider 与预算；使用合成内容做明确限额验收                                        |
| 附件扫描              | [附件扫描手册](../../infra/runbooks/attachment-scanner.md)；核验大小、哈希、隔离及失败关闭                               |
| 备份                  | [备份恢复](../../infra/runbooks/backup-restore.md) + [Windows 异机副本](../../infra/runbooks/windows-off-host-backup.md) |
| 知识空间与本地 Worker | 核对独立功能开关、授权、迁移和加密前置；不要一次性打开全部开关                                                           |

生产网络配置应允许已经批准的必要外呼，同时保留数据库和 Redis 的内部边界。不要以关闭 TLS 校验解决连接问题。

## 3. 日常检查

在实际部署目录使用对应的 Compose 配置执行。若安装了封装命令 `logion-compose`，优先使用它以加载正确配置。

```bash
docker compose ps
docker compose exec -T api python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/health/ready', timeout=3).read().decode())"
docker compose exec -T worker python -m logion_worker.health --live
curl --fail --silent http://127.0.0.1:8080/healthz
```

健康检查失败时先定位原因，再采取动作；不要反复重启掩盖问题。

| 周期                   | 检查内容                                            |
| ---------------------- | --------------------------------------------------- |
| 每日                   | 服务 readiness、5xx、延迟、OOM/重启、磁盘和任务积压 |
| 每日                   | 最近备份时间、校验结果、异机副本与告警投递          |
| 定期                   | 邮件失败/退信、过期邀请、异常设备与审计事件         |
| 定期                   | TLS 到期、依赖安全更新、保留策略与恢复材料可用性    |
| 升级前后               | 源码和镜像一致性、迁移头、真实登录与关键业务流程    |
| 至少每季度及关键升级后 | 独立空环境恢复演练和恢复耗时                        |

监控字段与聚合边界见[可观测性合同](observability-contract.md)。普通日志不应包含凭据、Cookie、私人正文或完整 Provider 输入输出。

## 4. 备份与恢复

1. 检查最近的加密 bundle 与相邻 SHA-256 文件。
2. 验证密文字节及认证解密，核对备份版本与密钥代际。
3. 将密文及校验信息保存到另一台受控设备；密钥分开保管。
4. 在独立空环境恢复数据库与附件。
5. 核对迁移头、数据数量、权限、引用与业务读取，记录实际 RPO/RTO。
6. 确认恢复测试完成后，再清理专门创建的测试资源。

详细命令见[备份恢复手册](../../infra/runbooks/backup-restore.md)。文件存在和复制成功都不能替代恢复成功；同机数据卷不构成完整灾备。

## 5. 升级与回退

1. 核对待升级提交、兼容性和对应发布说明。
2. 停写或进入维护窗口，完成可验证的升级前备份与异机校验。
3. 保留原源码、镜像、配置及密钥，使用固定 digest 切换应用。
4. 按版本要求迁移、启动并检查健康。
5. 验证真实登录、核心业务、同步、邮件和已启用能力。
6. 观察错误率、积压、资源、备份和告警，稳定后按保留策略处理旧制品。

应用回退与数据库回退是不同操作。正式写入后不能执行会丢失数据的降级；优先关闭相关能力、回退兼容应用并前向修复。不要使用 `docker compose down --volumes` 作为生产回退。

参考：[候选安全](../../infra/runbooks/candidate-security.md) · [恢复流程](../../infra/runbooks/release-candidate.md)。

## 6. 故障处理

| 现象               | 排查顺序                                                          |
| ------------------ | ----------------------------------------------------------------- |
| 应用打不开         | DNS/TLS → 反向代理 → Web/API readiness → 数据库/Redis             |
| Worker 不就绪      | 主循环心跳 → 依赖连接 → 对应队列连续失败与积压                    |
| 邮件未实收         | 邮件任务状态 → 发信域名/RAM/限流 → 服务商失败/退信 → 收件箱       |
| Provider 发现失败  | 服务地址与 DNS → 已批准出站网络 → TLS → 凭据与接口兼容性          |
| AI 运行不确定      | 先核对运行/尝试/预算状态，确认外部请求是否完成，再决定是否重试    |
| 同步卡住           | 保留 Outbox → 检查设备/epoch/权限 → 处理冲突 → 核对新旧客户端兼容 |
| 附件失败           | 配额与大小 → 上传队列 → 哈希/MIME → 扫描器和隔离状态              |
| 备份或异机同步失败 | 可用空间 → 密钥引用与权限 → 最近成功时间 → 校验和恢复结果         |

修复后重做最小验证，保留失败记录。报告问题时只提供脱敏时间、版本、错误码和计数。

## 7. 资料保管

源码仓库保存通用配置示例和手册。实际账号、地址、端点、密钥、数据备份、运行记录与验收报告保存在受控环境；临时测试账号和配置在验收后按既定保留规则清理。

文档更新与 GitHub 合并不自动部署线上服务；生产切换须绑定具体候选和实际验收。
